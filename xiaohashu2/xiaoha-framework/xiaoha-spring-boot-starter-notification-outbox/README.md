# Notification source outbox

Capture is disabled by default. Set `notification.events.enabled=true` only after deploying the compatible notification consumers and applying the reviewed outbox/error-table DDL to each source database. Configure `notification.enabled-at` as an ISO local datetime in Asia/Shanghai, for example `2026-11-14T18:00:00`; fractional seconds and missing cutoff are rejected at enabled startup. Match the same cutoff in the notification service. Original source event timestamps are compared and serialized at whole-second precision.

`NotificationOutboxWriter.save` requires the actual source database transaction. The first `(producer_service,business_key)` event is retained, including SENT rows. The UUID and payload stored by the first write remain stable on retry. The dispatcher scans its own service every second, claims a 15-second lease in a short transaction, sends outside that transaction with a 3-second timeout, and updates only the same lease owner/version. Expired leases are recoverable; MQ redelivery and a crash between broker confirmation and marking SENT are handled by notification recipient/business-key uniqueness.

`NotificationEventIsolationWriter.save(topic, originalPayload, reason)` stores permanently invalid source events in `t_notification_event_error`, using a SHA-256 identity over service/topic and the original payload. Source consumers acknowledge a rejection only after that durable write succeeds. An isolation database failure retries consumption. Missing comment reply targets get five retries before isolation. Metadata service outages continue retrying and are not classified as invalid routing. No table is accessed by either writer while capture is disabled.

Source changes preserve original like/count algorithms and count sending rules. Collection notification eligibility comes from the locked previous relation state; the count branch still uses the original upsert result. Comment insertions identify exact new IDs for KV/outbox while the original nonzero-batch count branch uses its existing BO list. Follow redelivery skips its count branch only after verifying that both relationship rows already exist.

Source tests use JUnit 5/Surefire 3.2.5. To avoid running existing service/MQ tests, select only `NotificationOutboxTest,CommentNotificationPersistenceTest,CommentSourceIsolationTest,FollowNotificationPersistenceTest,FollowSourceIsolationTest,NoteInternalQueryTest,CommentAccessTest,CollectSourceNotificationTest`. The outbox tests use an isolated in-memory H2 database; they do not start Spring Boot, RocketMQ, or apply source database migrations.
